# SurveyBench add-on: protocol record

Scope agreed with the user on 2026-09-30: content-based evaluation only (outline quality, content quality
with human reference, richness). No quiz-based evaluation: the gateway serves no embedding model, and the
released quiz generator samples questions with an unseeded RNG, so every system would get different questions.

## Benchmark
- SurveyBench repo at /home/juli/citation/SurveyBench (commit 8660218), 20 topics, human reference surveys in data/HumanSurvey.
- Published-system outputs shipped with the repo: AutoSurvey (GPT-4o), SurveyForge (GPT-4o),
  LLMxMR-V2 (Gemini-flash-thinking), OpenAI-DeepResearch. They were generated by the benchmark authors in 2025;
  we re-judge them, we do not regenerate them.

## Generation (Skill-Full, 1 run per topic)
- Same harness, prompt, reading mode ("full text when available, else abstract") and generator
  (deepseek/deepseek-v4.1-flash) as the DAS-Bench Skill-Full runs. Topic string = SurveyBench topic name.
- Run dir: evalbot@GPU host ~/das_eval/runs/deepseek-v4.1-flash_full_sb/sbNN; job file sb.jobs; 5 parallel.
- Held-out reference survey: each topic's human reference survey is on arXiv and would be found by open
  retrieval. It is withheld three ways, all active only when SB_EXCLUDE_FILE is set (sb* topics):
  1. wis_mcp_search.py (evalbot's copy only) drops it from search results by exact normalized title,
     arXiv id or DOI, and reports `stats.excluded_reference`. This is the only change to the skill.
  2. PreToolUse hook /opt/gen/sb_guard.py blocks WebFetch and Bash calls that name its arXiv id or a DOI
     (WebFetch also by title in the URL).
  3. Post-hoc audit (audit_leak.py): ledger and reference list must not contain it; blocked calls,
     filtered search hits and title mentions in tool results are reported.
- IDs: exclude.json (arXiv API exact title match for 7, Semantic Scholar title match for 13; all 20 exact).
- Live smoke test 2026-09-30 22:50: WebFetch and curl on arxiv.org/abs/2012.08752 blocked; search for the
  exact GNN reference title returned 9 papers with excluded_reference = 1.

## Conversion
- to_sb_md.py numbers the skill's headings hierarchically (the evaluator's outline and chapter parsers only
  read "## N Title" headings); "## References" is kept verbatim because the evaluator cuts the text there.
  Published-system outputs already use numbered headings.

## Judging
- Released scoring functions and prompts, unchanged: evaluate_content_compare, evaluate_outline, get_richness,
  and the released score parsers. Our loop (run_sb_eval.py) only stores per-topic results, which the released
  driver discards (it saves method averages).
- A topic whose judge output fails the released parser is re-judged, up to 6 attempts (the DAS-Bench cap).
- Main judge openai/gpt-4o-mini (the model named in the README and, for quiz context selection, in the paper;
  the paper does not name the content judge), 3 passes. Cross judge qwen/qwen3.5-397b-a17b (the DAS-Bench main
  judge), 2 passes. Gateway default sampling settings (the released code sets none).
- Every survey is judged against the same human reference; the evaluator truncates the generated survey at
  100k characters and the human survey at 150k characters.

## Known limitations to report
- The evaluator strips the reference list before every judgment: SurveyBench does not see citations at all.
- Systems differ in generator and date (2025 vs 2026); the comparison is system-level.
- Skill produces Markdown without figures; richness counts figures and tables per 100k characters.

## Same-generator baselines (added 2026-09-30 23:40 at the user's request)
Comparing with the published systems confounds the skill with its generator (they used GPT-4o / Gemini in 2025).
To isolate the skill, the two DAS-Bench baselines are rerun on the SurveyBench topics with the same generator:
- NaiveRAG-Own: one quick_search (query = topic, top 60, retry once if < 10) + one generation call.
- NaiveRAG-Pool: the Skill-Full run's ledger pool as candidates + one generation call.
Both use tools/naive_rag.py unchanged except `--exclude-dir`, which drops the held-out reference survey from the
candidate list with the same rule as the skill's search filter and records the count in `<run>/excluded_reference`.
Runs: pulled/naiverag-deepseek-v4.1-flash_{own,pool}_sb/sbNN (local, API calls only; no agent tools).

## Results (2026-10-01 02:15; analysis_sb.json / analysis_sb.txt)
All 7 systems x 20 topics judged: gpt-4o-mini 3 passes, qwen3.5-397b 2 passes; no failed items (3 re-judged).
Report outline and content separately, as the benchmark does; (content+outline)/2 is not a SurveyBench metric.
- Content vs same generator: gpt-4o-mini Skill-Pool -0.30 [-0.41,-0.19] (2/18 W/L), Skill-Own -0.13 [-0.24,-0.02];
  qwen Skill-Pool +0.06 [-0.01,+0.15], Skill-Own +0.35 [+0.22,+0.51]. qwen content is at ceiling (Skill 4.94,
  Pool 4.88; Skill pass-to-pass r = -0.11), so it does not discriminate among the top systems. Net: no consistent
  content gain from the skill's procedure on SurveyBench.
- Outline vs same generator, both judges: Skill lower (gpt -0.96 vs Pool, -0.70 vs Own; qwen -0.74, -0.49).
  Skill writes a flat thematic structure (12.2 numbered sections, 7.2 subsections vs Pool 12.8 / 14.3); the
  structure rubric rewards "clear section-subsection hierarchy".
- Published systems: all three deepseek conditions (Skill, Pool, Own) score above the published systems on content
  under both judges, so that gap reflects the 2026 generator, not the skill.
- Body statistics (not a judged quantity): distinct works cited in the body Skill 49 / Pool 164 / Own 40; distinct
  CamelCase/acronym method names Skill 140 / Pool 72 / Own 28; brackets with >= 5 refs Skill 0.5 / Pool 22.
  The gpt-4o-mini coverage gap therefore cannot be read as the skill naming fewer methods; its cause is not identified.
- Confounds: the released evaluator truncates the AI survey at 100k chars, so LLMxMR-V2 (298k), AutoSurvey (151k)
  and SurveyForge (111k) are judged on partial text; Skill/Pool/Own are not truncated. One generation run per topic.
- Benchmark disagreement: on DAS-Bench the same pair (Skill vs Pool) differs by TSQ +0.54 and HDQ +0.90 in the
  skill's favour under the main judge; SurveyBench gives no such gain.
